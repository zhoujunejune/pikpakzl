# EVENT10：手动10分钟 DeepSeek BTC方向分析

## 工作流程

1. 用户点击按钮，后台从现有 BTCUSDT 只读行情源取最新 tick、已收盘1m和5m K线。校验时效、交易对、价格与K线；不使用过期行情。
2. 以行情 tick 时间和价格作为参考起点，立即冻结时间戳、参考价、RSI/EMA/MACD/ATR/动量/成交量等特征。参考到期时间为起点 + 600000ms。
3. 仅当用户点击时发起 DeepSeek 分析，不自动按10分钟周期分析。AI输出必须为 UP 或 DOWN；如果返回 WAIT、非法 JSON 或调用异常，则至多重试4次，仍无法有效判断则记录失败，不伪造方向。
4. 10分钟后后台从同一公开行情源读取新 tick，必须在参考到期后15秒内、且样本本身不过期，才做 UP/DOWN 比较；持平不计入胜率。无法取得接近到期时间的真实数据则记录无法核验。
5. 前台单独显示参考价、模型方向、预计到期时间、真实取样时间、参考结束价、代理命中率和日志。后台专用持久化文件为 /var/lib/zl-event10/manual-sessions-v2.json，和旧自动任务互不混合。

## 官方事件合约与数据口径

当前价格来源是 BTC 公开行情代理，不是币安事件合约实际开仓或到期指数。币安 App 实际订单的开仓时间可能在提交后的下一秒，价格取该秒的事件合约指数。币安未公开事件合约交易接口，因此无法自动读取真实事件成交价格、官方结算结果或自动下单，不能把代理行情命中率标为官方事件合约胜率。

币安官方规则：https://www.binance.com/zh-CN/support/faq/detail/172247f1c4b8401ab106fb63900f3825

## API

- GET /event10/ : 中文前台（原有 Caddy Basic Auth）
- GET /event10/api/status : 状态与独立统计
- GET /event10/api/history : 已记录手动轮次
- POST /event10/api/start : 用户主动点击唯一触发入口，需要同源 Origin、自定义点击头和幂等请求 ID，不提交交易订单
- GET /healthz : 本地服务健康检查

服务只监听 127.0.0.1:13020，使用现有安全的 DeepSeek 服务器密钥配置。没有币安账户交易写接口，也不重启现有预测和合约交易引擎。

## 多源行情增强（V2）

手动点击时，会先并行采集公开 Binance USD-M 数据，然后从原 BTC 只读行情源冻结参考价格和采样时间。只采纳采样时间不晚于参考价时间的辅助指标，防止分析使用未来行情。采集内容：

- 1m 已收盘K线计算滚动10分钟涨幅/波动率/成交量变化
- Binance USD-M 15m 已收盘K线计算 EMA9/21、MACD、RSI 和最近区间
- 公开买卖盘20档深度与成交金额不平衡
- 最近最多1000组聚合成交中120秒内的主动买卖额与大额成交方向（不是完整订单流）
- USD-M 标记价格、指数价格与最近资金费率（不当作事件合约结算指数）
- USD-M 当前持仓量与最近5分钟历史持仓变化

使用公开只读 Binance fapi 端点，无 API Key、账户交易信息或订单提交。若阿里云区域访问受限（HTTP 451）、接口超时或时间戳失效，直接标记不可用，不改用规避地区限制的代理，不编造数据。记录每轮辅助数据的可用性及来源。自动 DeepSeek 分析仍只在用户手动点击后运行。

新增加 GET /event10/api/data-health 只读接口：当用户手动点击“检查实时数据接口”，才检测6类外部数据，不调用模型、不创建预测轮次。旧版历史统计隔离保留。本次尚未接入强平事件 WebSocket，后者可考虑单独增设服务并验证真实性，不能当成完整强平总额。


## 后台全天候交易事件采集（V3）

独立 systemd 服务 zl-event10-trade-stream.service 开机自动运行，使用币安2026公开 USD-M WebSocket 地址 wss://fstream.binance.com/market/ws/btcusdt@aggTrade。即使用户从未点击任何预测，WebSocket也连续订阅 BTCUSDT 的100ms聚合成交更新，并将每组收到的事件写入阿里云 /var/lib/zl-event10-stream/aggtrades-YYYYMMDDHHmm.ndjson 分钟分片。

采集服务与 EVENT10 DeepSeek、5分钟预测、合约实盘服务完全隔离；不使用交易账户API或密钥。独立采集服务默认监听 127.0.0.1:13021，外网只能通过原有带登录保护的 EVENT10 /api/stream-health 查看摘要，不能下载原始日志。文件保留最多12小时、总大小目标不超过400MB（会删除最老文件，不保证永久完整保留）。最近10分钟保存在有上限的内存环中，进程重启时可从磁盘恢复部分数据，但重启必然标记采集连续性中断。

持续记录 Binance aggregate ID、聚合内交易起止 ID、成交时间、事件时间、阿里云收到时间、价格、数量、主动买卖方向、名义成交金额。检查重复ID、跳号、迟到消息、网络断线、磁盘写入积压、最近事件时间延迟，断线后自动重连（指数退避）；缺口不会静默插值。发布时检查 WebSocket 实际连接并成功收到至少两组真实事件，仅服务存在不视为成功。由于币安100ms聚合成交并不等于所有原始逐笔撮合订单，任何统计均明确使用聚合成交流口径。

内存窗口60秒、300秒、600秒的主动买/卖名义金额、净额、大额成交组和事件时效供人工点击时 DeepSeek 使用。只有连通性、采样延迟和该窗口内的数据缺口检查全部通过时才传入模型；断线、重启或积累时间不足均记为不可用。模型调用、参考价和10分钟价格验证规则保持不变。采集器不自动产生预测信号、不提交交易订单，也不参与事件合约官方结算价计算。

实时运行状态：GET /event10/api/stream-health（需现有前台认证）显示 connected、accepted events、missingAggregateIds、gapCount、reconnectCount、lastEventLatencyMs 以及各时长窗口是否完整。该功能只针对连续成交采集，未添加强平事件、盘口WebSocket或价格指数修改。


## 聚合事件 vs 底层原始成交 ID 连续性修复

币安 USD-M @aggTrade 的 'a' 是聚合成交 ID，用于排查真正的聚合事件漏收；'f/l' 是包含的底层成交 ID 范围。由于官方文档明确指出 aggTrade 不包含保险基金和 ADL 等非普通市场成交，这些底层成交 ID 合法地出现跳号。只要聚合事件 ID 本身连续，单纯 'f/l' 跳号就必须作为信息性 'underlyingTradeIdSkips' 记录，不能错误累计到 gapCount 或导致 DeepSeek 丢弃全部1/5/10分钟窗口。真实聚合 ID 跳号、断线、积压、启动重建仍会标记完整性故障。任何已保存的旧诊断继续保留原始证据，不伪造历史。


## DeepSeek 双向证据核对 V3（2026-10-24）

EVENT10 生产模式仍然是用户手动点击一次、返回合法 UP 或 DOWN、以同一个公开行情代理参考价10分钟后核对（非币安事件合约官方结算）；模型仍是服务器配置的 deepseek-flash，不改API、密钥和其他合约/预测机器人。

每轮分析前根据同一冻结参考价时刻已取得的数据生成只读 decisionReview，整理1m/5m/15m EMA与价格变化、主动买卖成交、盘口深度、合法连续WebSocket流、持仓量变化等，明确发现：
- 多周期趋势背离、买卖成交与价格响应背离；
- 超常放量靠近高低区间的假突破或趋势延续风险；
- 大额主动买入但价格疲弱时的*可能*买盘被吸收风险（不是断言）；
- 买卖盘快照和真实成交量矛盾；
- 缺失/过时数据源及未验证的连续成交流。

prompt 要求 DeepSeek 独立考虑 UP、DOWN 两种假设及其反证后选择方向，禁止机械多头偏见、缺乏依据的反转假设及重复计数高度相关指标。返回仍需 direction UP|DOWN；额外存储模型的 upCase、downCase、decisiveEvidence、uncertainty 和 preflight decisionReview，前台显示供审计。confidence 仍是模型未经校准的主观信心，不是胜率。技术性API失败或无效响应最多重试4次，不编造方向。

这是**推理流程和输入质量改进**，不是重新训练 DeepSeek 的权重。仅有三条历史样本，不把误判样本作为硬编码看空规则或训练标签，也没有声称胜率已经提升。原历史记录/统计不重置，版本字段 decisionReviewVersion=EVENT10_BALANCED_EVIDENCE_V3_20261024 用于之后做真实前后对照。不会修改真实下单、盘口/成交流或自动生成预测的逻辑。

部署时若常驻聚合成交采集器源码未变且服务仍活动，不重启它，保护已积累的1/5/10分钟缓存和缺口统计。

## V4 分析纠偏：价格口径与反转风险

本次更改只针对用户点击后 DeepSeek 的分析输入与提示词，不改变币安实际订单、事件合约官方结算、手动启动、10分钟参考窗口或历史结果。

1. 参考价和1m/5m闭合K线仍来自原只读公开市场代理，合约订单流来自币安 USD-M BTCUSDT。两者是不同价格口径，绝对价格差异不能作为买卖盘吸收、破位或反转的证据。
2. 新增 REST 聚合成交**同一合约、同一样本时间窗口**的起止成交价、相对变化；仅当至少20组且覆盖20秒至120秒，才设置 verifiedPriceResponse=true，允许和同一数据的主动买卖差额配对评估；否则记录无法验证，不能臆测吸收。
3. 15分钟RSI低于等于30时标记超卖风险：如果更短周期转强，同时评估10分钟反弹和继续下跌。高于等于70时对称检查可能回落。这些仅作为双向风险证据，**不**强制UP或DOWN，也不是用13轮样本训练出的权重。
4. 新决策版本 EVENT10_PRICE_SCOPE_REVERSAL_V4_20261024，在新轮次历史中记录版本和证据。前台警告解释用简体中文。
5. 保留真实行情来源、时效检查、成交采集器和历史原样；新部署时若成交采集器代码没变，保持现有进程。
6. 未经统计验证，不能宣称命中率提高；旧版和新版须依相同公开行情代理结算口径比较。所有自动订单、支付、账户余额相关能力继续禁用。

## 2026-10-24 V6 动态价格结构 + AI 最终方向

参考开源 `Microoocity/10-Min-Event-ETH-Dynamic-Support-and-Resistance` 的 **ATR自适应回看、确认枢轴与支撑阻力分区** 思路，但独立实现面向BTCUSD公开参考行情代理的只读1分钟闭合K线算法；并从确认结束的最后3根K线验证方向持续性/突破。不会直接复制别人的高频交易策略、不使用未来K线、不会因为看见支撑就硬编码UP，或看见阻力就硬编码DOWN。

输入依旧沿用V5四组精简证据，仅增加一个 `priceStructure` ：最近支撑/阻力（以同源价计算）、支撑/阻力到参考价的ATR距离、近5根上涨下跌根数、最近3根闭合K线持续性和是否确认突破。参考价与USD-M永续合约成交价隔离，不能对不同市场绝对价格相减。提示词要求 DeepSeek High 独立分析上涨/下跌假设，并特别防止短价格动量、支撑阻力和短期持续性重复计票。

旧的人工启动、固定600秒代理核对、全量历史与中文解释仍保留；其他两套交易机器人进程不变。V6 独立统计，不保证胜率改善，不属于底层DeepSeek权重训练。无需真实下单权限。
